# التكاملات المقترحة

> **الوثيقة:** 12 · **المسؤولون:** AG-ARC (الأرشفة والمعايير)، AG-DIR (القرار)، AG-GIS (المكان)، AG-PUB (النشر).
> **تصنيف الحالة المعتمد في هذه الوثيقة:**
> - **مُنفَّذ:** يعمل في الإصدار الحالي ومختبَر.
> - **مشروط:** الشيفرة جاهزة للاستدعاء، ويعمل فقط إذا ثُبّتت الأداة محلياً أو توافر الاتصال المطلوب، ويتحقق التطبيق من ذلك قبل الاستعمال.
> - **مواصفة:** تصميم موثق دون تنفيذ؛ يُعامل في التطبيق على أنه غير متاح.
> - **جزئي:** جزء من الوظيفة منفّذ، والمطابقة الكاملة للمعيار مقترحة.
> - **مُصمَّم (تبادل يدوي):** لا تكامل برمجي، لكن صيغ التصدير المنفّذة تتيح نقل البيانات يدوياً.

## 2. تفصيل التكاملات

### 2.1 GitHub / git — مُنفَّذ

- **الغرض:** حفظ نسخ الوثائق المؤسسية وبطاقات الوكلاء والمهارات وحزم التلقين، وتتبع الإصدارات.
- **ما لا يُحفظ في git:** الأصول الصوتية والمرئية، والبيانات الشخصية، وقاعدة البيانات الحية. تبقى في الخزنة المحلية.
- **الضابط:** تقع القاعدة والخزنة والنسخ الاحتياطية افتراضياً في مجلد بيانات المستخدم خارج مستودع الشيفرة (المجلد `Turath` في المجلد الشخصي، أو ما يحدده المتغير `TURATH_HOME`)، ويستثني ملف `.gitignore` ملفات قواعد البيانات؛ وأي مستودع بعيد يكون خاصاً ما لم يُقرَّر غير ذلك.

### 2.2 faster-whisper — مشروط

- **الغرض:** مسودة تفريغ أولية لتسريع العمل.
- **القيود:** دقته في اللهجات المحلية غير مضمونة؛ لذا يُعامل مخرجه مسودة، ولا يُستشهد به قبل التصحيح الحرفي ومراجعة HUM-NATIVE.
- **الخصوصية:** يعمل محلياً؛ لا يُرسل الصوت إلى خدمة خارجية.
- **التحقق:** يفحص التطبيق وجود الحزمة والنموذج قبل عرض الخيار.

### 2.3 tesseract — مشروط

- **الغرض:** استخراج نص قابل للبحث من الوثائق المطبوعة.
- **القيود:** أداؤه في الخط اليدوي والمخطوطات محدود؛ فلا يُعتمد في قراءة المخطوطات، ويُعامل النص المستخرج طبقة بحث مساعدة لا نصاً محققاً.
- **التشغيل الحالي:** لا يتضمن الإصدار الحالي استدعاءً لـ tesseract من داخل التطبيق؛ فيُشغَّل خارجياً عند تثبيته، ويُودَع ناتجه النصي في الخزنة أصلاً مستقلاً يُذكر في مصدره (`provenance`) أنه ناتج تعرّف ضوئي عن الأصل الفلاني.
- **المقترح للإصدار التالي:** زر استدعاء من الواجهة، وحقل ربط صريح بين الأصل ومشتقه.

### 2.4 Claude Code / API — مشروط

- **المُنفَّذ:** حزم تكليف للوكلاء العشرين والمهارات الأربع عشرة تتضمن دستور الإدارة، وموجه الوكيل، وخطوات المهارة، وسياقاً من الأرشيف مقيداً بجداول القراءة المعلنة للوكيل وبصلاحيات المستخدم؛ والمحرك اليدوي (`manual`) متاح دائماً.
- **المشروط:** المحرك `claude_code` يتطلب برنامج Claude Code مثبتاً على الجهاز، والمحرك `api` يتطلب مفتاح الواجهة البرمجية في متغيرات البيئة. وإن تعذّر المحرك المطلوب يعود التطبيق إلى اليدوي.
- **التسجيل:** كل تشغيل يُسجَّل في `agent_runs` بمحركه وحالته (`package` · `draft` · `failed`)، ومخرجه مسودة لا تدخل الجداول البحثية إلا بإدخال بشري.
- **الضوابط:** لا تُرسل إلى محرك خارجي مواد بمستوى إتاحة `private` تخص معارف مقيدة إلا بقرار من AG-ETH (ضابط إجرائي)؛ وكل مخرج آلي يمر بالبوابات ذاتها؛ ويُفصح عن الاستعمال في بيان الذكاء الاصطناعي (الوثيقة 09).

### 2.5 Google Drive وZotero — مواصفة

| البند | Google Drive | Zotero |
|---|---|---|
| الغرض المقترح | استيراد مرفقات وتصدير مخرجات | مزامنة المراجع والاستشهادات |
| المقاربة المقترحة | واجهة برمجية بتفويض المستخدم؛ الاستيراد يمر بإيداع AG-ARC | استيراد CSL-JSON إلى `bibliography` مع إبقاء التحقق اليدوي من الوجود |
| البديل الحالي | الاستيراد اليدوي للملفات | الإدخال اليدوي |
| شرط التفعيل | قرار من AG-DIR بعد مراجعة الخصوصية | قرار من AG-DIR |

### 2.6 Omeka S — مُصمَّم (تبادل يدوي)

- **الغرض:** معارض رقمية ومجموعات عامة مختارة.
- **المقاربة:** تصدير المواد ذات `access_level = public` وموافقة نشر سارية فقط، بحقول Dublin Core، مع بيان الحقوق ووسم المسار البصري.

### 2.7 AtoM / ArchivesSpace — مُصمَّم (تبادل يدوي)

- **الغرض:** الوصف الأرشيفي الهرمي (مجموعة ← سلسلة ← ملف ← مادة) للمؤسسات الحافظة.
- **المقاربة:** تخطيط حقول `sources` و`historical_documents` و`manuscripts` إلى مستويات الوصف، وتصدير CSV.

### 2.8 Mukurtu CMS — مواصفة

- **الغرض:** الإتاحة القائمة على **بروتوكولات ثقافية** يحددها المجتمع (من يرى ماذا، ومتى).
- **المقاربة:** مواءمة مستويات `access_level` والقيود في `permissions` (مثل التقييد بحسب الجنس أو الأسرة أو المناسبة) مع بروتوكولات المنصة.
- **الأهمية:** يجسّد مبدأ احترام المعرفة المقيدة مجتمعياً المعتمد في الوثيقة 13.

### 2.9 OHMS — مواصفة

- **الغرض:** فهرسة المقابلات بمقاطع موضوعية وكلمات مفتاحية مزامنة مع التسجيل.
- **المُنفَّذ:** تصدير تفريغ كل مقابلة بصيغة SRT بطوابعه الزمنية.
- **المقاربة المقترحة:** تحويل `transcript_segments` و`oral_narratives` إلى صيغة قابلة للاستيراد في OHMS، للمقابلات المأذون بنشرها فقط.

### 2.10 QGIS — مُنفَّذ عبر GeoJSON

- **الغرض:** التحليل المكاني المتقدم وإنتاج خرائط الأطلس.
- **المقاربة:** تصدير طبقات GeoJSON من التطبيق (منفّذ)، وتُفتح مباشرة في QGIS.
- **الضابط (مُنفَّذ):** يقرّب التصدير إحداثيات كل موقع مؤشَّر عليه `sensitive` إلى 0.1 درجة ويضيف الخاصية `masked`؛ ولا يتضمن التصدير إلا الأماكن التي يحق للمستخدم قراءتها. والوصول إلى الإحداثيات الدقيقة يكون من سجل المكان نفسه لمن له صلاحية قراءته.

### 2.11 Wikidata — مواصفة

- **الغرض:** ربط الأماكن والأشخاص التاريخيين بمعرّفات مفتوحة لتحسين قابلية الربط.
- **الضوابط:** لا يُربط كيان إلا بعد تحقق بشري من التطابق؛ ولا يُرفع إلى Wikidata أي محتوى من مواد الرواة؛ والأحياء لا يُربطون.

### 2.12 IIIF — مواصفة

- **الغرض:** عرض الصور والمخطوطات عالية الدقة مع التكبير والتعليق.
- **المقاربة:** توليد ملفات Manifest للصور العامة، مع خادم صور مناسب يُقرَّر لاحقاً.

### 2.13 BagIt وPREMIS — جزئي / مواصفة

| البند | BagIt | PREMIS |
|---|---|---|
| الغرض | تغليف حزمة أرشيفية قابلة للتحقق | توثيق أحداث الحفظ والفاعلين والحقوق |
| ما هو منفّذ ويُبنى عليه | النسخة الاحتياطية: ملف مضغوط يضم لقطة متسقة من القاعدة، والخزنة، وبيان `manifest-sha256.txt`، وملف `bag-info.txt` | `change_log` (الأحداث والفاعلون والصورة السابقة واللاحقة) و`permissions` (الحقوق) و`assets.integrity` و`last_verified` |
| المقاربة المقترحة | استكمال بنية الحزمة لتطابق المواصفة (مجلد الحمولة، وملف إعلان الحزمة، وبيانات الوسوم) | تحويل سجلات التغيير والتحقق إلى أحداث حفظ |
| الاستعمال | المرحلة S16 والإيداع لدى جهة حافظة | كذلك |

### 2.14 Dublin Core — مُصمَّم (تبادل يدوي)

تخطيط مقترح للحقول:

| عنصر Dublin Core | الحقل في التطبيق |
|---|---|
| title | `title` (أو `name` / `term`) |
| creator | المؤلف/المصوِّر/الصانع |
| subject | الموضوعات والكلمات المفتاحية |
| description | `description` / `summary` |
| date | `date_text` / `date_taken` / `year` |
| type | `sources.kind` / نوع المادة |
| format | `assets.mime` |
| identifier | `id` |
| source | `source_ref` |
| language | `sources.language` |
| coverage | `place_id` / `region` / `emirate` (مقرّب عند الحساسية) والنطاق الزمني |
| rights | `rights` |
| relation | `asset_id` / `interview_id` / `source_ref` |

## 3. قواعد عامة لأي تكامل

1. **لا يُخرج تكامل مادة من نطاق إذنها.** التصدير المنفّذ يقتصر على ما يحق للمستخدم قراءته (الملكية والعضوية و`access_level` والمشاركات)؛ أما مطابقة المادة لنطاق الموافقة قبل الإتاحة العامة فتضمنها بوابة S13 والمراجعة البشرية، وفحصها الآلي عند كل تصدير **مقترح**.
2. **الأصل لا يُرسل:** تُرسل المشتقات أو الروابط؛ والأصل يبقى في الخزنة.
3. **الاستيراد إيداع:** كل ملف يدخل من تكامل يمر عبر AG-ARC وتُحسب بصمته.
4. **عرض الحالة الفعلية:** تعرض الواجهة لكل تكامل حالته، ولا يُوحى بتوافر ما هو مواصفة.
5. **التسجيل:** كل إيداع وتحقق ونسخ احتياطي وتشغيل وكيل يُسجَّل في `change_log` (مُنفَّذ)؛ وتسجيل عمليات التصدير **مقترح**.
